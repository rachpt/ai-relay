# 0011：公开准备与历史卫生

- 日期：2026-10-18
- 状态：已接受（用户明确授权）
- 关联：需求11、13.3；部分取代ADR0001第6项；开发记录2026-10-18-19

## 背景

用户要求为GitHub公开准备统一历史提交身份，删除旧JS/CMD参考实现及关联文件，检查历史敏感内容。此前默认保留旧脚本作为行为参考；旧脚本可能含真实部署配置，继续保留在项目目录会增加误上传风险。

## 决策

- 在仓库外创建仅当前用户/System可访问的恢复目录，备份完整Git元数据、可达历史bundle和拟删除的旧文件；验证bundle。备份不加入仓库、不发布。
- 使用git-filter-repo统一全部author/committer为 `rachpt <rachpt@126.com>`，保留原4个提交的树、顺序、时间和说明。仅设置仓库本地Git身份，不改全局配置。
- 从历史排除旧参考文件路径；审计确认这些文件原先已被忽略、未出现在可达历史，不把身份重写说成发现/清除了已泄露的密钥。
- 按授权删除根目录旧JS、CMD、PowerShell参考实现及关联日志/PID，共8个文件。`tools/` 原生开发脚本、配置和其他用户数据不在删除范围。
- 扫描全部历史文本blob及提交/标签消息，凭据检测禁用联网验证；用旧部署值的内存精确比对和隐私模式交叉复核。报告不打印密钥原文，候选人工区分真实秘密与合成测试。
- 清理当前仓库reflog和不可达旧对象，并验证对象完整性；旧身份映射移到私有备份，不发布旧历史。
- 保留本地数据与旧脚本忽略规则，不新增运行时依赖，不自动创建GitHub仓库或推送。

## 备选方案

- 仅设置user.name/email或.mailmap不会改变历史原始author/committer，不满足用户要求。
- 仅删除当前文件不能清理历史；仅依赖.gitignore也不能清理已跟踪对象。
- 删除全部历史/重新初始化Git会丢失开发记录与拓扑，没有必要。

## 影响与风险

所有历史提交哈希改变，旧克隆/备份仍包含旧历史；不能把它们合并回已清理分支。仓库外恢复资料可能包含敏感文件，只用于本地恢复。已公开或流出过的凭据无法靠Git重写撤回，仍应轮换。未经验证的dist/target产物不得随源码上传。
