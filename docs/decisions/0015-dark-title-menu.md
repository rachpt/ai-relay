# 0015：公开 API 深色标题／系统菜单

- 日期：2026-10-19
- 状态：已接受
- 关联：需求8.1；补充ADR0006，取代ADR0009中“popup可能与暗色应用不同色”的标题菜单显示边界，原生菜单／窗口命令路线不变。

## 背景

用户指出应用深色模式下标题入口的文件／代理／视图／帮助及系统命令仍为浅色。DWM深色标题栏不改变原生HMENU的客户区绘制，不能仅通过窗口主题保证弹出菜单深色。

## 决策

- 只在已解析深色主题下为既有标题／系统HMENU层级设置公开 `MFT_OWNERDRAW`，处理 `WM_MEASUREITEM`、`WM_DRAWITEM` 与 `WM_MENUCHAR`；`SetMenuInfo(MIM_BACKGROUND)` 设置菜单空白背景。不使用未文档化UxTheme ordinal、全局hook、系统色修改或自制popup窗口。
- 菜单仍由Windows负责展开、鼠标／方向键导航、启禁／radio／默认状态和系统命令；原命令分发与确认保持。保留 `MIIM_STRING`，绘制数据使用有界标量索引，不把Rust结构体指针存入itemData。
- 系统菜单字体由 `SystemParametersInfoForDpi` 读取，按真实文字、快捷键和DPI度量，区分正常／默认粗体、禁用／选中、当前页面和系统图标；绘制裁剪到item rect，SaveDC/RestoreDC恢复借用DC。
- 暗色适配在客户端菜单按钮模式也运行，不能被“不替换caption图标”的早返回跳过。主题／DPI改变先结束当前菜单跟踪，再恢复并重建；浅色／高对比度恢复原数据、位图和背景，不覆盖期间更新的可用状态。
- 菜单、字体、画刷按原生所有权释放；分配／安装失败回滚并保留可用的系统菜单。若异常恢复失败且画刷仍可能被菜单引用，宁可保留画刷，不释放仍被借用的资源。

## 备选方案

- 仅DWM／SetWindowTheme：不能覆盖HMENU菜单内容。
- 未公开暗色UxTheme API：与项目公开API约束冲突，不采用。
- 完整替换菜单窗口：增加输入、可访问性、子菜单定位及高对比度风险，当前不需要。

## 范围与限制

本决策仅覆盖标题／系统菜单及四组子菜单；托盘／表格右键菜单、消息框、文件对话框和月历仍可保持系统外观。不引入依赖、运行时、网络请求或配置迁移。保留可查询原生文字不等于已完成真实读屏验收；150%／200%度量和绘图回归也不等同实际多屏GUI验收。
