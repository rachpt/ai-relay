# 0018：原生深色月历颜色与翻月呈现

- 日期：2026-10-25
- 状态：已接受
- 关联：需求8.1；定点取代[ADR0016](0016-dark-native-date-picker.md)的弹出月历栅格着色路线，日期框本身仍保留原方案

## 背景与证据

用户报告深色月历翻到下一页后持续变亮。独立screen-only回归确实复现：初始深色，键盘／鼠标翻月后约95%像素变亮，并持续到1秒后，tint子类仍安装。队列取证确认月历`WM_TIMER.lParam != 0`、TimerProc地址属于COMCTL32；DispatchMessage直接调用它，绕过月历窗口过程，最后的浅色绘制没有再经过tint。原打印回归重新生成暗色栅格，不能证明屏幕未变白。

`BufferedPaintStopAllAnimations`实验即使返回成功也无效，不控制该控件内部TimerProc。继续扩大WM_PAINT／WM_TIMER覆画消息名单无法可靠覆盖此路径。

## 决策

1. 只对本组件拥有的深色、非高对比度弹出`SysMonthCal32`局部关闭视觉主题，使用公开`DTM_SETMCCOLOR`缓存＋当前实例`MCM_SETCOLOR`原生六色；calendar卸载tint，避免二次映射。原生直接绘制也使用深色源，不拦截／替换／终止原生TimerProc，不改系统动画偏好。
2. 日期框自身继续保留视觉主题与有界栅格着色；浅色／高对比度月历恢复默认主题和系统颜色。日历内容、国际化、日期范围、选日、键盘／鼠标及可访问性仍由原生控件维护。
3. 经典月历`TITLEBK`兼作星期文字前景，不能与`MONTHBK`同色。使用`TITLEBK=accent`、`TITLETEXT=on_accent`、`MONTHBK=surface`，兼顾两组对比度；接受原生箭头按钮的经典外观，不覆盖其命中语义。
4. 以最终主题／字体重新查询`MCM_GETMINREQRECT`及`MCM_GETMAXTODAYWIDTH`，保守保证client满足minimum并计入实际NC余量。不是用旧themed rect增加固定像素。
5. 同时调整原生容器：已复现月历child大于独立`DropDown`宿主，旧路线只调child导致右列／页脚被父容器裁切。只在当前calendar为child、直接父容器为同线程DropDown＋WS_POPUP时按child外框及原生inset调整宿主；必要时限制最终位置到目标显示器工作区，不缩小原生minimum。dropdown通知后仍保留排队收尾，避免native覆盖。

## 不采用

- 关闭整个窗口主题／修改系统动画：影响过宽。
- 轮询补画、主循环分发后补画或包装线程TimerProc：无法自然覆盖模态循环且增加生命周期风险。
- 完全自绘月历、伪造日期或吞计时器：破坏原生语义、超出本批必要范围。
- 将先前经典月历裁切失败改写为成功：保留旧记录，本次新增父容器尺寸证据与回归后再采用。

## 验证边界

四日期×96／144／192字体参数检查原生minimum、父容器包含、工作区、重复apply幂等、七列星期及日期ink、标题／今天页脚、原生命中、浅深／对比度恢复和日期不变；30轮开关导航GDI稳定。独立物理回归导航后不打印／不强制重绘。成品使用四日期screen-only专项，实际采样时间记录，瞬时帧不白与稳定帧前景完整分别断言。

真实150%／200%、多屏、真实高对比度、物理键鼠／读屏及完整日期矩阵仍按STATUS待验收；字体参数和有限帧不是连续视频或全部系统验收。结果与失败证据见[开发记录](../development/2026-10-25-04-dark-calendar-navigation.md)。
