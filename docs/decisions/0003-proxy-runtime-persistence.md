# 0003：反向代理运行时与配置提交边界

- 日期：2026-10-17
- 状态：已接受（当前开发增量方案，不替代最终需求）
- 关联：需求第 5、6、10、12 节；ADR 0002

## 背景与决策

采用 Tokio 1、Hyper 1、hyper-util 0.1、http-body-util 0.1、bytes 1 实现 HTTP/1.1 流式转发。TLS 采用 hyper-rustls 0.27、ring 和系统原生信任根；证书加载放到阻塞工作线程，证书与主机名验证保持启用。不引入外部语言运行时，ring 构建需要现有原生构建工具，运行无需单独安装 ring。

- 关闭 Hyper 连接取消自动重试，不跟随重定向；请求/响应不整体聚合，不自动解压。
- 活跃请求许可随响应体生命周期保留，另限制入站连接数；取消、超时及停机回收资源。
- 连接超时覆盖等待连接阶段；响应头计时从分配连接后开始，包含上传；读取空闲超时由下游读取驱动，不宣称为独立慢客户端写超时。
- 上游前缀移除末尾斜杠；请求路径等于前缀或以“前缀/”开头不重复添加。保留编码、点段和查询，不采用会规范化路径的 URL join。
- 当前拒绝开启尚未实现的正向代理、CONNECT、CORS；正式需求未删除，后续补齐。

GUI 通过有界命令和事件队列与后台协调线程通信。该线程拥有 Tokio runtime、配置 I/O 和 ProxyHandle；窗口消息循环不等待磁盘、TLS 初始化或线程 join。当前启动初始化限时 30 秒，宿主暂只接受不超过 30 秒的停机宽限期，正常退出最多等待约 36 秒；系统会话结束仅尽力通知，不阻止系统关机。

配置新建用不覆盖的 MoveFileExW，更新用 ReplaceFileW，同目录临时文件先 sync。最近备份为应用管理的 `.bak`；备份发布失败表示主配置可能已提交，必须向用户说明并保留恢复文件，不能当作从未保存。损坏或未来版本的已有配置不覆盖。

## 备选与影响

不采用阻塞 HTTP 客户端或在 GUI 中创建运行时；不手写 HTTP 解析器。临时文件加简单删除重命名无法满足 Windows 更新语义，故使用系统 API，但仍需处理 ReplaceFile 部分失败。

DPAPI 尚未实现，当前仅允许明确确认的明文持久化秘密；只启动可使用内存密钥。现阶段保存与启动分离，运行中需先停止，不假装完成需求中的一键保存应用、回滚和目录迁移。

## 验证与未决事项

本地模拟上游覆盖分段上传、SSE、取消、头/体/连接超时、认证、重定向不跟随及 POST 不重试；配置临时目录测试覆盖备份和失败恢复。GUI 端到端本地 mock 冒烟通过。尚未验证实际受信任 HTTPS 成功握手、完整性能、长稳和干净 Windows 分发。TLS 验证失败不得以关闭证书验证处理。
