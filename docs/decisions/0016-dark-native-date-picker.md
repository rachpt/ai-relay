# 0016：保留原生布局的深色日期框与月历

- 日期：2026-10-20
- 状态：已接受
- 关联：需求8.1、ADR0006；取代日期选择初期“聚焦／月历允许浅色”的外观降级，不改变日期、查询或时区语义。

## 背景

用户指出深色模式下聚焦日期框与弹出月历仍为白色。既有日期框只在闭合未聚焦且启用时覆绘；原生主题月历忽略部分公开MCSC颜色。早期关闭月历视觉主题曾造成200% DPI裁切，不能重用该方案。

## 决策

- 日期框和其短生命周期月历保留 Common Controls 原生视觉主题、字体、布局、窗口样式、选区、命中和键盘／鼠标行为；只深色安装模块本地绘制子类，不安装全局hook，不引入未文档化UxTheme接口。
- 借助公开 `WM_PRINT`／`WM_PRINTCLIENT` 获得控件原生栅格，写入有界32位top-down DIB；同步 `GdiFlush` 后做256级中性／强调色查表映射，再BitBlt到绘制DC。该缓冲只来自当前原生控件自身，不读取其他窗口／桌面，也不持久化用户文本。
- 白色表面映射到深色surface，黑色文字映射到浅色text；非线性灰阶保留禁用／抗锯齿可读性，彩色选中／焦点映射到accent。控件字段位置、选日、复选空值、界面文字及辅助功能树不由此模块重建。
- 绘制受重入和 `WM_SETREDRAW` 守卫；无借用跨原生回调，Rc在同步销毁／移除时保活。使用SaveDC／RestoreDC，原生几何查询非客户区边界；字体不新增所有者，DIB/DC每次绘制有界创建并归还，最大4,194,304像素（16 MiB）。分配失败转回原生绘制，不模拟成功。
- 浅色／高对比度移除着色子类；每次实际绘制前检查高对比度，避免系统通知排队期间错误着色。公开MCSC颜色保持原生作为映射源；字体和原生最小尺寸校正继续使用原方案。

## 备选方案

- 只设置MCSC颜色：在现有视觉主题下不能改变实际像素。
- 关闭主题：已知高DPI布局／绘制裁切风险，不采用。
- 完全自绘月历或替换popup：需重复实现日期范围、键盘、可访问性、国际化和DPI，当前收益不足。
- 未公开暗色API／全局主题hook：违反项目约束，不采用。

## 范围与风险

仅对模块创建的四日期框及其原生月历着色，其他下拉／托盘／消息框不扩大范围。栅格重映射不是任意系统主题像素的完整语义理解，原生动画瞬间和未来Windows绘制变化仍须实机复核；颜色不能替代可访问性验证。原生月历翻月有短暂动画期，测试须等原生消息处理后验证稳定帧，不把空动画帧当作选日失败。

## 验证

原生字体96/144/192、聚焦／禁用／空值／浅色／高对比度参数回退、DC恢复和30轮GDI通过。实际Debug／Release96 DPI日志及统计四控件、原生翻月／方向键／Enter／清空通过；两构建各84张离屏图和12张有遮挡保护的物理图通过，8轮GDI恒99。实际高DPI／多屏／真实高对比度／读屏仍待验收，见 [开发记录](../development/2026-10-20-01-dark-date-picker.md)。
