# 0009：原生标题栏紧凑菜单入口

- 日期：2026-10-18
- 状态：已接受
- 关联：需求8.1、ADR0006

## 背景

用户要求菜单放在标题栏内，类似编辑器hamburger，不再额外占菜单栏高度。需保留Win10/11原生边框交互及现有Win32技术路线。

## 决策

使用原生caption小图标位置显示三横线，自定义系统菜单顶部添加文件/代理/视图/帮助分组；WM_NCLBUTTONDOWN/DBLCLK HTSYSMENU及F10/Alt+M统一打开原生popup，Alt+Space和系统菜单项保留。仅替换ICON_SMALL，大图标/托盘产品图标不变。

## 备选方案

- 独立HMENU栏：最原生但多占一行，不符合用户要求。
- 完整自定义标题栏/无边框：可任意安排菜单按钮，但需处理DWM/命中测试/拖动/缩放/Snap/高对比度，当前收益不足以承担兼容风险。
- 标题区覆盖浮动子窗口：焦点、最大化和DPI边界复杂，不采用。

## 影响与风险

系统菜单含原生还原/移动/大小/最小化/最大化/关闭项目，保留而不是伪装成纯Web菜单。popup可能与暗色应用不同色。使用对齐自定义WM_SYSCOMMAND命令，复用现有确认/可用性，跟踪模态循环不持State借用；图标/菜单资源按native所有权管理。

## 验证及未决

native四项测试及96DPI自动化菜单检查通过，物理点击/键盘、读屏、多屏及高DPI菜单仍需人工验收。不引入未公开API、依赖、运行时或网络操作。
