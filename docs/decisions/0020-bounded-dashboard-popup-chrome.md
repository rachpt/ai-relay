# 0020：概览有界整帧呈现与月历宿主边沿

- 日期：2026-10-30
- 状态：已接受
- 关联：需求8.1／8.2；补充[ADR0018](0018-native-dark-calendar-navigation.md)及[ADR0019](0019-fluent-presentation-tokens.md)，不替换经典月历六色、原生导航或输入边界

## 背景与证据

用户报告概览采样刷新闪烁、图表跳动，以及深色月历外侧白边。

真实 `SS_OWNERDRAW STATIC` 回归显示：原生 `WM_SETTEXT` 同步触发1次背景请求及1次owner draw；仅抑制 `WM_ERASEBKGND` 不足以绕开这条路径。旧图表在目标DC直接执行背景、卡片、文字和逐段曲线，绘制过程可能被呈现；未知提示切换时绘图区顶部在68／88 DIP间变化。

月历自身及原生 `DropDown` 的NC在本机均为0像素，离屏NC检查不能复现用户白边。独占桌面下保持经典深色六色，仅卸载局部边沿适配后，屏幕采样测得 `DropDown` 的3像素客户区空隙含1,676个亮色像素；重绘calendar后仍存在。重新适配后为0，calendar客户区逐像素不变。该证据定位本机同类白边，不推断所有Windows版本均有相同几何。

## 决策

1. 仍使用原生STATIC及公开窗口子类：图表 `WM_SETTEXT` 交给 `DefWindowProcW` 存储原生文字，随后仅排队非擦除失效，避免STATIC的同步清空／重画；`WM_PAINT`／带有效选项的 `WM_PRINTCLIENT` 向原owner发送 `WM_DRAWITEM`。展示层不持应用State或堆指针，原生文字读取仍可获取完整指标。
2. 仪表盘在私有兼容DC／bitmap内绘制完整帧，一次 `BitBlt` 呈现；保留目标clip及origin，GDI资源按帧释放。瞬时bitmap上限16,777,216像素，常规32位约64 MiB；尺寸／资源分配／拷贝失败回退相同直接绘图，不返回模拟成功或空白。无需整个窗口 `WS_EX_COMPOSITED`，不重排页面或同步更新整棵控件树。
3. 绘图区顶部固定88 DIP，提示只变文字；1／2／5刻度留顶部余量，流量显示二进制速率单位、计数显示十进制单位。折线保留全部有效样本，普通主题只在端点／转折标记，高对比度第二序列保留逐样本空心方形，避免短虚线退化后误似未知缺口。精确文字及120点／120秒采样、未知断线口径不变。
4. 月历仍按ADR0018使用原生经典六色，接受原生浅色箭头按钮。只子类当前calendar和严格识别的同线程原生DropDown，绘制实际NC及宿主客户区空隙，排除所有直接子窗口；不改样式、尺寸、命中、计时器、日期内容或全局系统色。浅色／高对比度移除局部呈现并恢复原主题。
5. 月历打印按父窗口请求部分与子窗口遍历分开保存／恢复DC，防止NC-only clip吞掉明确请求的children；屏幕补画避开no-redraw、几何事务及同步卸载／销毁。状态用独立Rc保活，不引用应用State。

## 不采用

- 全局禁绘、频繁 `WM_SETREDRAW` 切换或页面级合成：扩大显隐／生命周期边界，不能只解决图表自己的同步擦除。
- 重新对整个月历栅格tint或包装TimerProc：会重引入ADR0018已证实的翻月白帧或输入／动画风险。
- 自绘日期、透明导航子窗口、去掉原生边框样式：超出用户外框白边范围，增加尺寸／命中和恢复成本。本批早期导航呈现尝试已收敛，不纳入最终实现。

## 验证与限制

Windows串行回归覆盖文本更新的0同步绘制／0背景请求、固定几何、打印flags、隐藏更新、整帧与直接绘制像素对照、DC／clip／origin与GDI资源、原生月历父子包含／七列／页脚／浅深恢复、打印子窗口及同步销毁。Debug概览／modern矩阵及四日期暗色翻月、独立屏幕白边前后取证通过限定范围，见[开发记录](../development/2026-10-30-01-ui-width-calendar-chart.md)。

并非连续视频证明整个页面绝无闪烁，也不代替真实150%／200%、多屏、Win10／11差异、真实系统高对比度、读屏或资源耗尽验收。原生文本API回归不证明全部MSAA／UIA事件通知行为。
