# 文档导航与记录规范

## 阅读顺序

1. [需求规格](../REQUIREMENTS.md)：功能、默认值、边界和验收。
2. [开发约束](../AGENTS.md)：代码、安全、验证及记录规则。
3. [当前进度](development/STATUS.md)：已完成、未完成和下一步。
4. [架构说明](ARCHITECTURE.md)：模块边界及计划中的调用关系。
5. [开发指南](DEVELOPMENT.md)：环境、验证和发布检查。
6. [设计决策](decisions/README.md)：重大取舍及其依据。
7. [开发记录](development/README.md)：每批实际变更与验证结果。

- [页面、统计与日志交互设计](UI-DESIGN.md)：四 Tab、多维分析、实时文件日志和清理规则（部分已实施，见 STATUS）。

- [便携预览使用说明](PORTABLE.md)：数据、安全、CLI及发布限制。

## 信息边界

- `REQUIREMENTS.md` 是验收基线；ADR 不能隐式删减需求。
- 架构图、路线和目标不代表已经实现，实际状态以 `development/STATUS.md` 为准。
- 开发记录保留当时事实；后续变更通过新记录补充，不将历史失败改写为成功。
- 文档不放真实密钥、现网上游地址、固定局域网 IP 或本机用户路径。
- 新增文档应链接到本导航或对应目录索引，避免形成无人维护的孤立文件。

## 每次开发结束检查

- 是否更新相关测试与使用说明？
- 是否执行适用的验证并记录失败或未执行原因？
- 是否新增本批开发记录并更新 STATUS？
- 是否需要 ADR 或需求修订？
- 是否遵守用户数据保护与旧脚本移除授权范围，避免重新引入敏感参考实现？
